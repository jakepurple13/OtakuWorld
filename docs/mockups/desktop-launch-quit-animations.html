Desktop launch & quit motion

Three launch and three quit animations per app. Each stage is the main window's content area: launch ends on the app, quit ends on the desktop. The first card in each row is the concept you described. Each app offers only its own three, plus Off and Fade, chosen from a new page in Desktop Settings.

Reduced motion is on, so nothing autoplays. Use Replay on a card.

How it would plug in

  • Launch: a full-window overlay composable above the nav host in DesktopUi.kt. It starts when the native -splash: card hands off to the first window, so the progress bar in NativeSplash stays as it is.
  • Quit: onCloseRequest (and the macOS ⌘Q quit handler) sets closing = true instead of calling exitApplication directly. The overlay runs, then calls exitApplication() in its finished callback.
  • Ending on the desktop: these mocks fade to the wallpaper. Chosen: quit ends on the wallpaper. The main DecoratedWindow stays as it is. On quit, a short-lived transparent, undecorated window opens at the same bounds with a snapshot of the app, the main window hides, the animation plays there, then exitApplication().
  • Settings: a Motion row in each app's Desktop Settings (PlatformSettings.kt) opens a Launch & quit animations page. The list is Off, Fade, then the app's own three. Animations never cross between apps. Each app stores its two choices in its own desktop settings. Any click or key skips a launch animation, and every animation stays under about 3.5 seconds.
  • Common tools: Animatable + Modifier.graphicsLayer for transforms, graphicsLayer { clip = true; shape = … } or drawWithContent { clipRect / clipPath } for reveals, and Canvas for strokes, dots and noise.
