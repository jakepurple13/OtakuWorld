Custom repos sheet proposals

The sheet behind Extensions ⋮ → Custom repos today is a bare list of URLs with a text field. Nothing says what a repo is, what happens after you add one, or whether it worked. Each phone below is clickable: add a repo, remove one, try the error case.

  • No explanation of what a "custom URL" is
  • No feedback after Add (did it load? how many extensions?)
  • Raw URLs only, hard to tell repos apart
  • Tap-anywhere copies (hidden action)
  • Delete needs a dialog, no undo
  • Count "2" in the top bar has no label

AExplained list

Smallest change. Keep the shape, add a one-line explainer, name + status on every repo, swipe-style remove with undo.

How it works

  • Add field pinned at bottom with a Paste chip and inline error under it.
  • New row slides in as Checking…, then turns into N extensions or Couldn't load.
  • Copy becomes an explicit icon. Remove is instant, snackbar offers Undo.

Compose

  • Modifier.animateItem() on rows, AnimatedContent on status pill, SnackbarHost inside the sheet.

BCheck before add

Teach first, then confirm. Pasting a link shows what's in the repo before it is saved.

How it works

  • Empty state walks through 3 steps: find a repo link, paste it, extensions show up in Get extensions.
  • Pasting triggers a fetch. A preview card shows repo name, extension count and languages, plus a trust warning.
  • Add repo saves only after a good fetch. Bad links never reach the list.

Compose

  • Preview = AnimatedContent over Idle / Loading (shimmer) / Found / Error. Needs a per-URL repoClient.fetch(url) call.

C · 1 CATALOGMangaWorld

One layout for every app. Here only Mihon is installed.

One layout, driven by data

  • Summary line, then cards. Problem repos sort to the top. No tiles, no filter chips, nothing that depends on catalog count.
  • Every card has a catalog badge once a catalog accepts the link. Failed links get no badge.
  • All catalog wording comes from the installed catalogs: Checking Mihon…, Supported: Mihon, Mihon can't read this link.
  • Badge colour comes from the catalog's position in the list, not its name.

In kmpuiviews

  • No "Mihon" / "Aniyomi" / "CloudStream" strings. The sheet reads catalog.name from each installed KmpExternalCustomApiServicesCatalog.
  • Needs checkRepo(url): RepoCheck? per catalog (null = not my format). Merge: first non-null wins, all null = Not supported.
