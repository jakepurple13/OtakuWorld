OtakuWorld Telemetry Plan

A new :telemetry KMP module owns analytics, crash reporting and crash-log breadcrumbs. Firebase lives only in the full flavor of :telemetry:android. Everything else gets interfaces through Koin.

targets android · jvm · ios firebase in full only desktop + iOS no-op ~100 call sites to migrate
1 · Architecture

Two modules, one contract

The KMP Android plugin (com.android.kotlin.multiplatform.library) has no product flavors, so :telemetry can't hold noFirebase/full source sets. The flavor split moves one level down into :telemetry:android, a plain Android library that copies the sharedutils flavor setup. Gradle matches flavors automatically when an app depends on it.

Why the app picks the Koin module

:telemetry's androidMain can't depend on :telemetry:android, because that would be a cycle. So kmpuiviews sees only interfaces, and each app's Koin start includes the binding module for its platform. Gradle flavor matching decides whether the Android module is no-op or Firebase.

What leaves other modules

  • firebaseCrashLibs removed from kmpuiviews androidMain, UIViews, and the four app modules.
  • expect recordFirebaseException / logFirebaseMessage / analyticsScreen deleted from Platform.kt and its three actuals.
  • Crashlytics keys and user properties in OtakuApp.firebaseSetup() move to Telemetry.start().

Stays where it is

  • Crashlytics Gradle plugin and task disabling in buildSrc (it's per app).
  • Firebase Auth, Firestore, Remote Config, Performance. They aren't telemetry.
  • GlobalExceptionHandler and CrashActivity. The handler only gains a CrashReporter call.

Contract (commonMain)

interface Analytics {
    fun log(event: AnalyticsEvent)
    fun screen(name: String)                      // replaces analyticsScreen()
    fun setUserProperty(name: String, value: String?)
    fun setEnabled(enabled: Boolean)
}

interface CrashReporter {
    fun log(message: String)                      // breadcrumb; replaces logFirebaseMessage(), also printLogs in debug
    fun recordException(throwable: Throwable)     // non-fatal; replaces recordFirebaseException()

    fun setEnabled(enabled: Boolean)
}

2 · Ground rules

What may be sent

Never sent: item titles, item or chapter URLs, search text, note text, custom list names, account emails, file paths.

Allowed: source and extension names, media type, enum values, booleans, and counts or durations bucketed (0, 1-5, 6-20, 21+).

Firebase limits: event names ≤ 40 chars, ≤ 25 params per event, values ≤ 100 chars, 500 distinct event names, 25 user properties. Crashlytics keeps 64 custom keys, a 64 KB breadcrumb log, and 8 non-fatals per session.

Free from Firebase (no code)

first_open, session_start, user_engagement, app_update, os_update, app_remove, crash-free users, plus device, OS, country, and app version on every event.

Opt-out toggles (proposed)

Settings › Privacy & security gets Share usage analytics and Send crash reports. Both default on in full and are hidden in noFirebase. They call setEnabled on start and when changed.

4 · Crash logging

What a crash report carries

A Crashlytics report has three layers: custom keys (state at the moment of the crash), breadcrumbs (the last ~64 KB of log() lines), and non-fatals (caught exceptions recorded on purpose).
